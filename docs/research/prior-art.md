# Existing tools connecting AI sessions or agents across machines and people

> Decision brief — research sweep of 2026-07-14. Every key fact cites a live source
> fetched that day; an independent verifier re-checked each one (verdicts below).

## TL;DR

The space is crowded for same-machine, single-developer agent coordination (mcp_agent_mail at ~2k stars, dozens of smaller MCP bridges) and for vendor-hosted shared assistants (Anthropic's Claude Tag, launched June 23, 2026, gives a whole Slack channel one shared Claude). But no shipped tool today does cross-PERSON, cross-VENDOR session-to-session messaging with owner approval — developer A's Claude Code asking developer B's ChatGPT a question is unserved, and an open Claude Code feature request (#28300, Feb 2026) shows the demand with no vendor response. The niche is genuinely open, but Claude Tag's expansion roadmap and A2A's Linux Foundation momentum are the two clocks ticking on it.

## What it is

A competitive-landscape scan across five neighbor categories. (1) Same-machine/same-owner agent coordination MCP servers: Dicklesworthstone/mcp_agent_mail (identities, inboxes, threads, file leases; 2,025 stars; HTTP-capable so technically multi-machine, but designed for one person's coding agents on shared repos), plus a long tail (cc2cc 13 stars, agent-comms-mcp 0 stars, session-bridge, claude-chatgpt-agent-bridge task broker that reuses local claude/codex CLIs). (2) Vendor shared assistants: Claude Tag — one persistent, channel-scoped Claude that whole teams tag in Slack; Team/Enterprise beta. (3) Agent-to-world email: AgentMail ($6M seed, Mar 2026) gives agents real email inboxes — infrastructure, not team session messaging. (4) Protocols/registries: Google-origin A2A (Linux Foundation, spec v1.0.1 released May 28, 2026, 24.8k stars) is service-to-service agent interop with no human-owner-approval concept; NANDA (MIT) is a v0.3 work-in-progress RFC; Coral Protocol is token/crypto-flavored roadmap-ware with no recorded funding. (5) Cross-owner agent networks: OpenClaw has opt-in agent-to-agent messaging (sessions_send, disabled by default, per community docs mostly within one gateway) and Moltbook, a public agent-only social network (1.5M registered agents, acquired by Meta on March 10, 2026) — public posting, not private team messaging.

## What adopting it buys us

Reframing: "adopting" here means learning from neighbors instead of building me-too. The scan buys three things. First, validation: demand for cross-machine agent collaboration is documented in Anthropic's own issue tracker (#28300, a production microservices use case, unanswered since February), and the explosion of same-machine coordination tools (mcp_agent_mail's 2k stars in eight months; Yegge's adjacent beads at 25k stars) shows developers want agent-to-agent infrastructure badly. Second, a free integration playbook: every successful neighbor ships as an MCP server, which is exactly how we reach Claude Code, ChatGPT, Cursor, and Codex without per-vendor work; mcp_agent_mail's mailbox metaphor (identities, inboxes, threads, searchable archive) is a proven UX for agents. Third, clear differentiation axes nobody occupies together: cross-person (messages route between different humans' sessions), cross-vendor (Claude ↔ ChatGPT), owner approval (B approves before B's session answers), and open source self-hostable. Claude Tag has cross-person but is one shared Claude, Slack-only, Anthropic-only, closed. mcp_agent_mail has cross-vendor but is one-operator, no approval concept. A2A has cross-org but targets headless enterprise services, not interactive sessions with humans attached. The intersection is empty — that is the product.

## What it costs us

The open niche has real headwinds. Claude Tag is the incumbent-shaped threat: for an all-Claude team on Slack it already solves "my colleague's AI context is reachable" with zero setup, Anthropic says 65% of its product team's code flows through the internal version, and it explicitly plans to expand beyond Slack — if it grows session-to-session semantics and OpenAI ships a symmetric feature, the vendor-neutral middle gets squeezed. Second, the long tail of near-zero-star bridge tools shows this is easy to prototype and hard to make matter; a weekend MCP server is not a moat, so the value must come from the approval/identity/trust layer and polish. Third, mcp_agent_mail could pivot into our lane cheaply — it already runs as an HTTP server reachable across machines; we would be competing with a 2k-star incumbent on adjacent ground. Fourth, protocol risk: if A2A extensions eventually standardize human-in-the-loop cross-org messaging, a bespoke wire format becomes legacy; tracking A2A compatibility costs ongoing effort. Fifth, the OpenClaw/Moltbook saga (risky instruction sharing between cross-owner agents is now an arXiv-documented failure mode) means security posture — approval gates, capability limits, no prompt-injection relay — is table stakes, not a nice-to-have, and it is expensive to get right.

## Recommendation

Build it — there is no direct competitor. Nothing shipped today lets colleague A's Claude Code session message colleague B's ChatGPT session with B's approval; every neighbor misses at least one of cross-person, cross-vendor, or approval. Position precisely against the two closest threats: versus Claude Tag, we are "your own AI talks to your colleague's own AI" (peer sessions, mixed vendors, self-hosted, open source) rather than "one shared Claude in a channel" (Anthropic-only, Slack-only, closed); versus mcp_agent_mail, we are cross-person with human approval and identity/trust rather than one developer's agent swarm on a shared repo. Concretely: ship as an MCP server first (the proven universal adapter for Claude Code, ChatGPT, Cursor, Codex); steal the mailbox metaphor (inboxes, threads, searchable history) because agents and users both understand it; make owner approval and prompt-injection containment the headline feature, citing the Moltbook research as the cautionary tale; stay wire-format pragmatic but document an A2A-compat story so enterprise buyers don't veto us. Do NOT build another same-machine coordinator (saturated), an agent email service (AgentMail owns it, funded), or anything token/registry-shaped (Coral/NANDA are immature and off-mission). Move soon: issue #28300 sitting unanswered is an invitation, but Claude Tag's post-Slack expansion could close the window within quarters.
