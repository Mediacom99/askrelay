# Market research — The vendor clock: will a platform ship cross-person AI-session messaging natively, and when?

> Market go/no-go input, researched 2026-07-16 against live sources;
> every evidence item independently re-checked (verdicts below).

## TL;DR

No vendor has shipped, announced, or credibly hinted at askrelay's exact shape — person-to-person, approval-gated messaging between individuals' AI sessions. All four are converging on a different topology: shared org-owned agents living in team chat (Claude Tag in Slack, ChatGPT workspace agents in Slack, Teams channel agents) plus intra-session multi-agent orchestration and A2A service-agent meshes. That shared-teammate model partially absorbs the "ask a colleague a question" job when the knowledge lives in shared systems, and a single-vendor org-scoped Claude Code session mesh is a realistic 6–18 month threat; the cross-vendor, cross-org, self-hosted position looks structurally unserved by vendors for 24+ months.

## Assessment

The specific product shape — human A's session asks human B, B approves, B's AI answers from B's private context, B reviews — is shipped by nobody, announced by nobody, and hinted at by nobody as of mid-July 2026. That is a verified absence across Anthropic, OpenAI, Microsoft, and Google primary sources. But the adjacent pressure is real and fast-moving. All four vendors converged in Q2 2026 on the shared-teammate model: one org-owned agent in Slack/Teams that everyone queries. For questions answerable from shared systems (repos, docs, chat history), that model removes the need to ask a colleague at all — no approval, no latency — and it will absorb a meaningful slice of askrelay's headline use case inside single-vendor orgs. The sharpest single-vendor threat is Anthropic extending Claude Code agent-teams messaging (primitives already shipped, Feb 2026) from session-scoped to org-scoped for Enterprise/Team customers; given their cadence (Cowork preview→GA in 3 months; Tag shipped in June with expansion promised), I'd put a same-vendor, same-org variant at plausible within 6–18 months, though it is not currently announced or hinted. What no vendor shows any incentive to build: cross-vendor (Claude↔ChatGPT↔Codex), cross-organization, self-hosted, with approval-as-the-product. Vendor interop energy is going into A2A for org service agents, which validates askrelay's protocol alignment while leaving the personal-session layer empty. Confidence: high on the absence today; medium-low on the 6–18 month single-vendor estimate (extrapolation, not evidence).

## Implications for askrelay

The window is open now but the intra-team, same-vendor core case — Kosmoy colleagues all on Claude Code — is the most exposed segment, exactly the first-user base. If Anthropic org-scopes agent-teams messaging, askrelay's answer must already be deployed and differentiated, so speed to a working v1 matters more than breadth. Position the product deliberately on what survives vendor entry: (1) cross-vendor bridging (a Claude Code session asking a ChatGPT-using colleague — no vendor will build the other half); (2) cross-org use (contractor↔client, OSS co-maintainers — vendor workspace models all stop at the tenant boundary); (3) self-hosted/data-sovereign relay (relevant to EU buyers like Kosmoy; every vendor offering is cloud-only); (4) approval-gating and untrusted-content quarantine as the product, where vendors treat governance as admin dashboards, not per-message human consent. Marketing should not lead with "ask your teammate's AI" alone — Claude Tag's shared-channel Claude answers that pitch inside Slack-centric orgs. Lead with "across tools, across companies, on your own server, with consent." Also note the answering-side moat: shared org agents only know shared context; askrelay uniquely reaches B's live local session state (uncommitted code, terminal, private repos), which no channel bot can see. Watch Claude Tag's expansion announcements and any Claude Code cross-session feature as the tripwires.

## Open questions

- What is the duplicate/parent issue behind claude-code #33788, and does it show maintainer engagement or a roadmap label indicating cross-session messaging is being built?
- Does A2A 1.2's signed-agent-card identity model get extended to personal/per-user agents (e.g., via Entra Agent ID for individuals), which would give vendors a fast path to cross-user agent messaging inside their clouds?
- How much of real colleague-question traffic is answerable from shared context (absorbed by Claude Tag / workspace agents) vs. requiring the colleague's private session state? No usage data exists yet; askrelay's own pilot at Kosmoy could measure this.
- Will OpenAI's workspace agents add tenant-to-tenant or user-to-user agent invocation (their Slack deployment and API triggers are one config change away from it)?
