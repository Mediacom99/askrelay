# Vendor ToS / acceptable-use constraints on automated and unattended AI session participation (Anthropic, OpenAI, Cursor)

> Decision brief — research sweep of 2026-07-14. Every key fact cites a live source
> fetched that day; an independent verifier re-checked each one (verdicts below).

## TL;DR

Both vendors prohibit driving a consumer chat session programmatically: Anthropic's Consumer Terms ban automated/non-human access except via API key or explicit permission, and since February 2026 Anthropic explicitly bans third-party tools from routing requests through Free/Pro/Max OAuth credentials (server-side enforced; opencode dropped Claude subscription support after legal requests). OpenAI's ChatGPT Terms ban programmatic extraction of Output, credential sharing, and rate-limit circumvention, with a documented history of account deactivations for unofficial-API/headless use. The safe pattern — and effectively the only compliant one — is our connector running as an MCP server inside the vendor's own client (Claude Code, claude.ai, ChatGPT, Codex), with any headless/daemon participation mode forced onto API keys. Relaying one user's model output to another user is fine under both vendors' terms provided it is labeled AI-generated.

## What it is

This brief maps the legal/policy perimeter for our core loop (one person's AI answering another person's AI, possibly unattended) across four document families. Anthropic: Consumer Terms (effective Oct 8, 2025) prohibit accessing services "through automated or non-human means" except via an Anthropic API key "or where we otherwise explicitly permit it," and ban account sharing; the Usage Policy (effective Sep 15, 2025) requires consumer-facing chatbots to disclose they are AI and bans human impersonation; the Claude Code legal-and-compliance page states OAuth is "intended exclusively" for subscription holders' "ordinary use of Claude Code and other native Anthropic applications," and that "Anthropic does not permit third-party developers to offer Claude.ai login or to route requests through Free, Pro, or Max plan credentials on behalf of their users" — Agent SDK products should use API keys. OpenAI: ChatGPT Terms of Use prohibit "automatically or programmatically extract data or Output," sharing account credentials, circumventing rate limits, and representing Output as human-generated; Codex docs sanction non-interactive use (codex exec, GitHub Action) but steer automation to API keys or Enterprise-provisioned access tokens. Commercial/Business terms on both sides carry no automated-access ban — the constraint is consumer-plan-specific. Cursor's ToS (Jan 13, 2026) has no comparable automation ban.

## Maturity

These are actively-enforced, recently-revised policies, not dead letter. Anthropic: Consumer Terms effective 2025-10-08; Usage Policy effective 2025-09-15; Commercial Terms effective 2025-06-17; the Claude Code legal-and-compliance page gained the explicit third-party-credential ban in February 2026, with The Register (2026-02-20) reporting opencode removed Claude Pro/Max support citing "anthropic legal requests," account bans in early 2026, and community trackers reporting server-side OAuth blocking phased in Feb–Apr 2026 (full enforcement ~2026-04-04, community-sourced). OpenAI: Usage Policies last updated 2025-10-29; Services Agreement effective 2026-01-01; Codex docs (learn.chatgpt.com, current) document non-interactive mode and device auth (beta); ChatGPT Scheduled Tasks got a dedicated management hub in June 2026 (9to5Mac, 2026-06-17) and runs unattended server-side on Go/Plus/Pro/Business/Enterprise. Enforcement history on the OpenAI side is mostly automated and opaque: community forums document deactivations for bot/script access and reverse-engineered endpoints, including false positives. Cursor ToS effective 2026-01-13. Admin control surfaces are shipped and current on both sides (Claude Code managed-mcp.json / allowlists; ChatGPT workspace connector publishing with action-level controls).

## What adopting it buys us

Designing to the compliant pattern from day one buys survivability and enterprise deployability. The pattern: our connector is an MCP server that the vendor's own client connects to — Claude Code / claude.ai connectors on the Anthropic side (usage covered by the user's subscription because calls happen inside the official client), ChatGPT connectors/apps and Codex MCP on the OpenAI side. Under this shape, cross-user relay is clean: both vendors assign Output ownership to users, and nothing in either ToS restricts giving your output to another person or another AI, provided it isn't presented as human-generated (both vendors) and isn't used to train competing models. Unattended operation has sanctioned lanes we can build on: ChatGPT Scheduled Tasks runs server-side without the user present; Codex has a documented non-interactive mode (codex exec), a GitHub Action, and Enterprise "Codex access tokens" for trusted non-interactive workflows; Claude Code has no explicit unattended prohibition (limits merely "assume ordinary, individual usage"). Being admin-approvable is also a feature: Claude Code's managed-mcp.json/allowlists and ChatGPT's workspace connector publishing (admin-only, frozen tool snapshots, read/write action controls) mean an IT admin can roll our connector out to a whole team — the same surfaces that could block us become our distribution channel.

## What it costs us

Hard constraints on product shape. (1) We can never hold, proxy, or accept a user's claude.ai/Claude Pro/Max OAuth token, and we cannot ship a standalone daemon that answers "as the user's Claude" on subscription credentials — that is now explicitly prohibited and server-side blocked; the same applies to building on the Agent SDK with subscription auth. Any always-on headless persona must be API-key-funded (usage-based billing, separate provisioning). (2) On OpenAI, we cannot script the ChatGPT web/consumer app at all (programmatic extraction ban, enforced by deactivations); participation must go through ChatGPT's own connector/apps surface or the API. Whether third-party harnesses may use "Sign in with ChatGPT" Codex auth is officially unanswered — prudent to assume Anthropic-style tightening. (3) Auto-reply mode inside a consumer client is a gray zone: an MCP-triggered loop that answers a colleague's AI without the seat-holder present isn't clearly "ordinary, individual usage" of Pro/Max limits, and heavy use risks rate-limit throttling or account action against our users. (4) Team/Enterprise deployments require admin approval on both platforms (Claude org connector settings, managed-mcp allowlists; ChatGPT admin-published connectors with action controls), so onboarding is gated on IT. (5) Every relayed message must be labeled AI-generated (Anthropic AUP disclosure duty; OpenAI human-generated-representation ban).

## Recommendation

Commit to the "inside the vendor's client" architecture: ship the connector as an MCP server that Claude Code, claude.ai, ChatGPT, Codex, and Cursor attach to; never touch user OAuth tokens; never emulate or drive a consumer session. Offer exactly two participation modes and be explicit in docs: (a) attended/approval mode — messages surface in the user's own client session and the human's client sends the reply (fully compliant on all plans); (b) unattended auto-reply mode — powered only by API keys (Anthropic Console / OpenAI API key or ChatGPT Enterprise Codex access token), never by a consumer subscription. Do not promise subscription-funded unattended personas; that exact pattern got opencode a legal request and its users bans. Mark all relayed content as AI-generated in the message envelope (this also satisfies both AUPs and is cheap). Treat "auto-reply inside a live Claude Code session via hooks" as experimental/at-your-own-risk pending Anthropic clarification — ask Anthropic sales the question the docs invite. Build admin-approvability in from v1: publishable to ChatGPT workspace connectors, allowlistable by serverUrl in Claude Code managed settings, with a one-page admin security doc. This constrains scope less than it appears: the compliant shape is also the best security shape (human approval in the loop by default).
