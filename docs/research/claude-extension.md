# Claude-side extension points for inter-session messaging (attach points for colleague-to-colleague message delivery)

> Decision brief — research sweep of 2026-07-14. Every key fact cites a live source
> fetched that day; an independent verifier re-checked each one (verdicts below).

## TL;DR

Claude Code (CLI) offers two immediate mechanisms: Channels (research preview, Telegram/Discord/iMessage) and Hooks (31 event types, production-ready). MCP sampling and Managed Agents webhooks are supplementary but require polling or custom tooling. claude.ai web, Agent SDK, and Tool Runner lack native event injection. Claude Tag (Slack) is the only org-level multi-person mechanism but requires admin setup.

## What it is

Extension points are the official attach points on Claude products where external systems can inject messages or events into a running session without user typing. They span: Claude Code (CLI) hooks and channels, MCP sampling/elicitation (request-driven from server to client), Managed Agents events API and webhooks, Agent SDK custom tools, and Claude Tag in Slack (thread-scoped remote sessions). Each surface (CLI, web, API, desktop, Slack) has different capabilities; most are production or beta, but Channels is research preview.

## Maturity

Claude Code Hooks: production-ready, 31 event types with additionalContext support, CLI-only. Channels: research preview (announced March 20, 2026), Telegram and Discord stable, iMessage added March 27, 2026, Bun-based plugins, Anthropic allowlist during preview, enterprise admins must enable channelsEnabled setting. MCP: current stable spec 2025-11-25 (Nov 25, 2025); release candidate 2026-07-28 adds async Tasks and extensions framework. Sampling/elicitation sparse adoption (VS Code Insider, limited Claude Code coverage). Managed Agents: beta (2026-04-01 header required), webhooks shipped, but session state-change events only. Agent SDK: production-ready, self-hosted, no built-in async listening. Claude Tag: public beta, requires Team/Enterprise org and Slack workspace pairing (no per-seat charge; billed by usage from org balance).

## What adopting it buys us

A clear attach point for a colleague's message to surface in a running Claude session without copy-paste. For your product (colleague A's Claude session sends question to colleague B): Channels provides a direct path for Claude Code users (external chat → session), Hooks enable custom-tool subscription patterns, Managed Agents API allows programmatic event sending from external services. For multi-person teams: Claude Tag is the only native shared-session mechanism (Slack integration, org-level, no per-user setup). MCP extensibility is open but requires custom server implementation; sampling/elicitation are immature in clients. The choice hinges on target surface (CLI-only vs. cross-platform) and whether you accept Anthropic-hosted (Managed Agents) or require self-hosting (Agent SDK + custom).

## What it costs us

Channels are in research preview: API surface may change, feature gating by enterprise admins (channelsEnabled setting) required for Team/Enterprise orgs, Bun dependency for plugins. Hooks are CLI-only; no cross-platform story. MCP sampling/elicitation adoption is sparse; clients don't universally support them, and they're request-driven (server can only ask client, not push unilaterally). Managed Agents webhooks only notify on state changes, not arbitrary external events; polling the events API is required to push content into a session. Agent SDK has no async listening natively; custom tool + streaming input is the only path and requires architectural changes (streaming prompt, hook to keep stream open). Claude Tag requires org setup and Slack integration; doesn't work for individuals or non-Slack teams. Cross-platform story is fragmented: claude.ai web has no hooks, channels, or event injection; Tool Runner is stateless per-turn, not persistent.

## Recommendation

For MVP use case (two colleagues on Claude Code): Choose Channels if users are willing to add Telegram/Discord bots and you're comfortable with research preview churn. Hooks + custom tool is more stable but requires custom MCP server or polling. For production and cross-platform: Managed Agents + events API is the most durable (Anthropic-hosted, webhooks, stable beta). Claude Tag is the fastest for Slack-native teams but requires org setup and only works in Slack. Avoid: Agent SDK custom tooling alone (no async listening, fragile), MCP sampling for this use case (immature client support, request-driven model is backwards). Plan for: channels feature stability (follow 2026-07-28 MCP RC and Channels research preview maturity); Managed Agents v1.0 release (currently beta); cross-platform story (claude.ai web has no event injection as of now). Recommend starting with Managed Agents API + custom webhook receiver if you control both sides; Channels if locked to Claude Code users.

## Key facts

1. **Claude Code Hooks support 31 event types, including 11 that can inject additionalContext (SessionStart, Setup, UserPromptSubmit, PreToolUse, PostToolUse, PostToolUseFailure, PostToolBatch, Stop, SubagentStart, SubagentStop, Elicitation). additionalContext is capped at 10,000 characters; overflow is saved to a file.**
   - Source: <https://code.claude.com/docs/en/hooks.md>
   - Verified: Fetched official Claude Code hooks documentation; reviewed hook event lifecycle and additionalContext field specifications.
2. **Claude Code Channels is a research preview feature (announced March 20, 2026; Telegram and Discord stable, iMessage added March 27, 2026) that pushes events into a running session. Requires --channels flag at launch. Telegram, Discord, and iMessage are the only officially supported platforms. Each plugin is a Bun script.**
   - Source: <https://code.claude.com/docs/en/channels.md>
   - Verified: Fetched official Claude Code channels documentation; confirmed launch dates and platform list. Verified Bun requirement and plugin architecture.
3. **MCP current stable specification is 2025-11-25 (released November 25, 2025). It includes sampling (server requests LLM completions from client) and elicitation (server requests user input). Notifications are one-way JSON-RPC for lifecycle signals. Next release candidate is 2026-07-28, introducing async Tasks and extensions framework.**
   - Source: <https://modelcontextprotocol.io/specification>
   - Verified: Fetched MCP specification main page; cross-referenced with MCP blog announcement for 2026-07-28 RC and MCP 2025-11-25 changelog.
4. **MCP sampling (server initiates LLM calls) and elicitation (server requests user input) require explicit client capability declaration and human-in-the-loop approval. Adoption is sparse: VS Code Insider supports elicitation; Claude Code support for sampling/elicitation is limited (as of Feb 2025). claude.ai web does not support sampling or elicitation; only tools.**
   - Source: <https://modelcontextprotocol.io/docs/concepts/sampling>
   - Verified: Fetched MCP sampling specification; verified client capability negotiation and approval model. Confirmed client adoption status via search results and documentation cross-reference.
5. **Claude Agent SDK is self-hosted; users deploy it on their own infrastructure. query() supports one-shot or multi-turn sessions (continue: true resumes most recent session; resume: session_id targets specific session). The SDK has no built-in mechanism for external events to wake or notify a running session; custom tools or streaming input are required.**
   - Source: <https://code.claude.com/docs/en/agent-sdk/sessions.md>
   - Verified: Fetched Agent SDK sessions documentation; reviewed continue, resume, fork, and streaming input patterns. Confirmed self-hosting requirement and lack of native async listening.
6. **Claude Tool Runner (Claude API) is beta and handles the agentic loop over user-defined tools. It supports per-turn hooks for approval, error interception, result modification, and retries. Tool Runner is not for persistent sessions; each query() call is independent or resumed via session ID (Managed Agents only).**
   - Source: <https://platform.claude.com/docs/en/agents-and-tools/tool-use/tool-runner.md>
   - Verified: Fetched Tool Runner documentation from Claude API platform; confirmed beta status, hook support, and per-turn execution model.
7. **Claude Managed Agents (Claude API) runs in Anthropic-managed cloud sandbox. Sessions are persistent; send events programmatically via /sessions/{id}/events. Webhooks notify on session state changes (started, idled, terminated, outcome_evaluation_ended) and vault/deployment events, but do not enable arbitrary external event injection. Managed Agents is beta (requires managed-agents-2026-04-01 header).**
   - Source: <https://platform.claude.com/docs/en/managed-agents/overview.md>
   - Verified: Fetched Managed Agents overview and webhooks documentation; confirmed beta status, webhook event types, and session event model. Verified stateful design and Anthropic hosting.
8. **Claude Tag (Team/Enterprise org feature) runs in Anthropic cloud sandbox. Each Slack channel or thread is backed by a remote session. Multiple team members can mention @Claude in shared channels; memory is scoped to the channel. No per-seat charge; billed by org usage balance. Requires org-level setup (Owner provisions identity in Admin settings).**
   - Source: <https://claude.com/docs/claude-tag/overview.md>
   - Verified: Fetched Claude Tag overview documentation from claude.com; confirmed org setup requirement, billing model, memory scoping, and multi-user Slack interaction.
9. **claude.ai web supports remote MCP servers for tools only (connectors via Settings > Connectors). Sampling and elicitation are not supported. No hooks, channels, or programmatic event injection. Managed Agents is available via API only, not via web interface. Desktop app (Claude Desktop) also supports remote and local MCP servers.**
   - Source: <https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp>
   - Verified: Fetched Claude Help Center article on remote MCP connectors; cross-referenced with search results confirming web vs. desktop MCP support and absence of hooks/channels in web.
10. **Claude Code as MCP client supports local stdio, remote HTTP/SSE, and WebSocket transports. MCP scope can be per-project (.mcp.json), per-user (~/.config/claude/mcp.json), or global. During preview, Channels plugins are restricted to Anthropic allowlist; enterprise admins can set allowedChannelPlugins in managed settings to restrict further or approve internal plugins.**
   - Source: <https://code.claude.com/docs/en/mcp.md>
   - Verified: Fetched MCP quickstart and full reference documentation; confirmed transport types, config scopes, and enterprise controls for Channels plugins.
11. **Claude Code Hooks PreToolUse event supports both additionalContext injection and updatedInput (tool input modification). Stop and SubagentStop use additionalContext for non-error feedback without blocking. No hook can replace the user prompt directly; UserPromptSubmit only allows context injection alongside the submitted prompt.**
   - Source: <https://code.claude.com/docs/en/hooks.md>
   - Verified: Fetched hooks documentation; reviewed PreToolUse, UserPromptSubmit, Stop, and SubagentStop event specifications and their additionalContext/updatedInput support.
12. **MCP notifications are one-way JSON-RPC messages with no response expected. They signal lifecycle events (notifications/initialized) and dynamic updates (notifications/tools/list_changed). They do not enable server-to-client push of arbitrary content; they are for metadata changes and protocol signals.**
   - Source: <https://modelcontextprotocol.io/specification>
   - Verified: Fetched MCP specification; confirmed notification message format and use cases. Verified they are not a general push mechanism.
13. **Claude Code Channels requires Bun. Enterprise/Team orgs must have channelsEnabled set to true in managed settings before channels can deliver messages. Individual Pro/Max users on claude.ai can use channels without org approval. During research preview, only Anthropic-allowlist plugins (Telegram, Discord, iMessage) or --dangerously-load-development-channels for local testing are supported.**
   - Source: <https://code.claude.com/docs/en/channels.md>
   - Verified: Fetched Channels documentation; confirmed enterprise controls, individual user permissions, and plugin allowlist mechanism.

## Independent verification

**Overall:** The brief is structurally trustworthy — every surface it names is real and correctly situated (Channels research preview with --channels/Bun/allowlist, Hooks with the 10k additionalContext cap, Managed Agents beta with the managed-agents-2026-04-01 header and /v1/sessions/{id}/events, Claude Tag as a Team/Enterprise Slack feature billed from an org usage balance, MCP 2025-11-25 stable with a 2026-07-28 RC), and its bottom-line recommendation hierarchy is defensible. But it is unreliable in exactly the details a decision would be built on: 5 of 13 key facts failed verification. The hook inventory is wrong twice over (30 events, not 31; Elicitation does not accept additionalContext while UserPromptExpansion does), Tool Runner's headline capability list includes approval hooks the docs explicitly disclaim, the MCP config-scope file paths are invented (~/.config/claude/mcp.json does not exist; local/user scopes live in ~/.claude.json), the RC is credited with introducing Tasks that actually shipped experimentally in 2025-11-25, and the sampling/elicitation adoption picture is badly stale — Claude Code has shipped full elicitation support (v2.1.76, March 2026) with dedicated hook events, directly contradicting the brief's 'limited as of Feb 2025' framing (a date at which elicitation did not yet exist in the spec). Two further gaps bear on the recommendation itself: the costs section wrongly says polling is required to push content into a Managed Agents session (the events API pushes directly), and the recommendation of Managed Agents as 'most durable' omits its documented ineligibility for ZDR/HIPAA. Treat the brief's map of surfaces as sound, its recommendation as plausible, and every specific number, path, hook name, and adoption statement as needing the corrections above before use.
